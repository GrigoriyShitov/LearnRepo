# Практическое задание 9

## Задание

Развернуть работающий **Gitlab** с раннером, запушить туда все касающееся *только* образов основного приложения (без инфраструктурных частей и без композ файлов)

Сделать свой **Gitlab CI/CD** пайплайн (`.gitlab-ci.yml`). Требования:

- Наличие этапа сборки образа основного приложения (приложений), а так же образа с fluentd
- Минимум одна джоба - тегированная
- Наличие этапа “тестирования” кода (придумать любой синтетический тест самостоятельно). Сделать этот этап ДО этапа сборки - главное чтоб этот синтетический тест отрабатывал и не давал пайплайну выполняться дальше, если джоба упала
- Добавить правило, чтоб пайплайн осуществлял шаг сборки автоматически только для веток `main/master/develop`, а шаг тестирования - всегда
- Добавить файлы `README.md` (краткое описание вашего проекта) и `CHANGELOG.md` (история изменений, можно например сначала запушить код, потом сделать `.gitlab-ci.yml` и упомянуть в файле)
- \*Придумать и добавить еще один этап пайплайна, например сканирование кода

## Проверка результата

- Гитлаб и его раннер успешно развернулись (`docker-compose-cicd.yml`)
- Авторизоваться в гитлабе (`/etc/gitlab/initial_root_password`, исчезнет через сутки)
- Создать токен для авторизации (*Preferences → Personal access tokens*)
- Создать пустой проект, пушнуть локальный код в удаленный репозиторий (подсказки есть в самом проекте после создания)
- Создать раннер (*Settings → CI/CD → Runners*) и подключить (`$ gitlab-runner register …..` в контейнере раннера). В списке раннеров должен появиться и гореть зеленым
- В `config.toml` раннера добавить/заменить строчки

  ```toml
  volumes = ["/cache", "/var/run/docker.sock:/var/run/docker.sock"]
  network_mode = "host"
  ```
- Добавить файл `.gitlab-ci.yml`, свой или содержимое из примера. Пушнуть, проверить что пайплайн отработал (все зеленое в последнем прогоне Pipelines)

## Отчетность

- файл `.gitlab-ci.yml`
- скриншот успешно отрабатывающего пайплайна
